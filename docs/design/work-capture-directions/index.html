新建工作项：四个本质不同的方向

现状是 15 个字段平铺在一个滚动 modal 里，其中 14 个是可选的，但视觉上全都在逼你填；原生日期控件、新建/编辑共用一张表单。 四个 mock 分别回答同一个问题：“捕获一个想法的最小动作应该是什么？”每个页面右上角都有「▶ 播放演示」，也可以直接上手点。

全部为模拟数据 · 方向 A 的 “AI 解析” 是前端定时器伪造，用于评审交互，不代表真实延迟
✦ Charter structures it for you
A

速记 + AI 结构化

推荐 · 本质解

唯一入口是一个输入框。倒进一句话或一段 Slack 原话，卡片零等待落板，AI 在后台把标题、优先级、截止、来源、验收标准解析成 chips，人只纠错、不填空。原文永久留底。

为什么强捕获成本≈0；唯一用上了产品自身 agent 能力的方向；“猜测”显式标黄，可信
代价需要一次小模型调用（可先纯本地规则起步）；解析错误需要好的纠错动线
B

渐进披露 Modal

Modal 只留「标题 + 补充说明」两个输入，其余全部收成底部一排 chips：要什么点什么，弹小面板设置；背景/验收标准藏在 More。复杂度从推送式变成拉取式。

为什么强纯前端一天量级；零新增延迟/成本；键盘全可达；立刻不再“low”
代价本质仍是人肉填表；只是把表单叠好了，没有减少信息劳动
!high · #label · @aug 20
C

行内速添 + 侧栏详情

彻底干掉 modal。按 N，列顶出现一张“正在成形的卡片”，回车连续入板；!high、#label、@日期 边打边解析。详情/编辑全部在侧栏，顺手消灭了新建/编辑共用表单的问题。

为什么强捕获动作最快（一次按键）；不打断看板语境；速记语法零成本零延迟
代价速记语法要学；来源/背景这类字段离入口更远，靠事后补
D

新建即详情页

没有“表单”这个中间态：点 New 直接进入这条工作项自己的页面，标题像文档标题，属性是行内一列，验收标准是真清单。写到哪保存到哪，回看板时卡片已经在了。

为什么强新建、查看、编辑三态合一；重工作项（要写很多背景）体验最好
代价捕获要离开看板全屏切换；对“只想快速记一笔”的场景太重
怎么看：四个方向可以混搭——A 是本质解（AI 替人填空），C 是它最顺的容器（行内入口 + 侧栏纠错），B 是最便宜的止血（先把表单叠好），D 适合做卡片点开后的最终形态。 建议评审顺序 A → C → B → D；每页都能真实打字、点 chips、开弹层，右上角「▶ 播放演示」约 20 秒走完关键流程。 无论选哪个，两件事都会顺手做掉：换掉原生日期控件、把编辑模式从新建表单里剥离。
