Editor 入口重设计

问题：左下角的 Editor 按钮点下去的结果取决于隐藏状态，而且没打开项目时是一片空白。下面是先诊断，再给三个本质不同的方向——每个都能点。

现状：一个按钮，三种结果（源码事实）

点击 EditorsetSurface('workspace')
→
有会话打开时展开这个会话的工具画布（和"编辑器"半毛钱关系没有）
有项目、无会话打开当前项目的编辑器视图
什么都没打开一片空白 + 一行小字"Open a project to edit files"——你截图里的状态

根因：Editor 被放在了全局导航栏里，看起来像一个去处（和 Sessions、Work 并列），但它实际上是一个依赖上下文的工具——没有项目它就没有意义。源码注释自己都承认这是旧版全屏 IDE 撤掉之后留下的"兼容垫片"。按钮没错，是它的身份错了。

方向 A：删掉它编辑器跟着上下文走推荐
方向 B：升格它Files 成为一等目的地
方向 C：浮层化编辑器不是面，是随叫随到的手术刀

删掉全局按钮，编辑能力归还给拥有它的上下文

这个方向赌的是：你的产品主线是"会话 → 验收"，不是手写代码。想改文件的时刻永远发生在某个上下文里——看 agent 改了什么、在项目里翻代码。那就让编辑器只在那些地方出现。

  • 空白死路从物理上消失——没有入口就没有空态
  • 能删掉那个"兼容垫片"状态，状态机变简单
  • 导航栏底部只剩 Settings，语义干净：底部=全局工具
  • "我就想开个文件改两行"少了一键直达（缓解：⌘K 里保留命令）
试一下：① 在 Sessions 里点消息里的文件路径；② 切到 Projects → 点项目 → Files 标签。注意左下角已经没有 Editor 了。

编辑器彻底浮层化：哪里点到文件，哪里滑出编辑器

最激进的方向。赌的是：在这个产品里，"编辑文件"永远是某件事的中途动作，从来不是目的。那就取消"编辑器面"这个概念——任何地方点到文件路径，编辑器作为浮层滑出来，改完即走，你从不离开当前上下文。

  • 零导航成本：不切页面、不丢上下文、没有"回去"的问题
  • 和已有的 FileLens 机制同源，实现是顺水推舟
  • 重度编辑（多文件、分屏、长时间）体验受限
  • "浏览整个项目的代码"没有自然入口，需要 Projects 兜底
试一下：在 Sessions 或 Work 看板里点任何文件路径，编辑器从右侧滑出；✕ 关掉，你还在原地。

我的推荐：A 为主干，C 做补充；不选 B

A + C 其实是一体的：全局导航删掉 Editor 按钮（A），编辑器归属两个真实上下文——会话里点文件走浮层（C，FileLens 已经存在，顺水推舟），想整体浏览/编辑一个项目走 Projects → Files（A）。⌘K 里保留"Open Editor"命令给肌肉记忆兜底。

为什么不选 B：B 治好了"行为不可预测"，但它把编辑器抬成一等目的地，等于宣布这是个传统 IDE——和整个产品"会话是主面、编辑器是验收工具"的骨架相反。而且 7 个主导航项太挤了。

反对 A 的最强理由：刚打开应用、什么都没有、只想快速改个文件的人，路径从 1 步变 2 步（Projects → 项目）。我认为可以接受——这个动作在这个产品里本来就不该是第一动作。
